# MASTER PROMPT: Build a Professional, Human-Designed Website (Avoid AI/Vibe-Coded Appearance)

I want you to develop and maintain this website as a professionally designed and engineered software product.

**My most important requirement: The final website must NOT look AI-generated, prompt-generated, template-generated, or vibe-coded.**

It should look like a genuine product designed by an experienced UI/UX designer and developed by a professional software engineering team.

Do not simply focus on making the website visually attractive. Focus on design quality, usability, functionality, consistency, performance, accessibility, security, and maintainability.

Follow ALL the instructions below throughout the development process.

## 1. DESIGN PHILOSOPHY

- Design with a clear visual identity and intentional design decisions.
- Avoid generic AI-generated SaaS website aesthetics.
- Do not blindly follow popular AI-generated website layouts.
- Create a design appropriate for the actual purpose and audience of this project.
- Prioritize simplicity, clarity, usability and professional appearance.
- Every design element must have a reason to exist.
- Do not add elements just to fill empty spaces.
- Avoid unnecessary visual complexity.

## 2. STRICTLY AVOID THESE AI-GENERATED DESIGN PATTERNS

Do not use these design patterns unless there is a genuine design reason:

- Excessive purple, blue or pink gradients.
- Gradient backgrounds on every section.
- Excessive glassmorphism and frosted-glass cards.
- Neon colors, glowing borders and glowing buttons.
- Unnecessary floating circles, blobs and decorative shapes.
- Excessive rounded cards and pill-shaped components.
- Putting every piece of content inside a separate card.
- Repeating the same three-column card layout throughout the website.
- Oversized headings without proper visual hierarchy.
- Randomly scattered icons and illustrations.
- Emojis as substitutes for professional interface icons.
- Unnecessary floating elements.
- Excessive shadows and borders.
- Random animations and transitions.
- Fake dashboard charts and meaningless statistics.
- Generic hero sections with meaningless marketing slogans.
- Unnecessary badges such as 'AI Powered', 'Next Generation' and 'Revolutionary'.
- Random stock images that have no connection to the website.
- Excessive whitespace or overcrowded layouts.

## 3. PROFESSIONAL UI/UX REQUIREMENTS

### Typography
- Use a maximum of two suitable font families.
- Maintain consistent font sizes and font weights.
- Establish a clear typography hierarchy.
- Avoid unnecessarily oversized text.
- Ensure readability across all screen sizes.

### Colors
- Establish a consistent brand color palette.
- Use primary, secondary, background, surface, text and status colors appropriately.
- Avoid introducing random colors in different components.
- Maintain sufficient text contrast.
- Use gradients only when they genuinely improve the design.

### Layout and spacing
- Follow a consistent spacing system.
- Maintain proper alignment and proportions.
- Use appropriate content widths.
- Avoid inconsistent margins and padding.
- Use cards only when they improve content organization.
- Make each page visually consistent without making every page look identical.

### Components
- Maintain consistent button, input, dropdown, modal, table and navigation styles.
- Use appropriate icons from Lucide or Material Icons.
- Use consistent border radii.
- Use subtle shadows only when necessary.
- Avoid unnecessary component decoration.

## 4. CREATE A DISTINCT DESIGN FOR EACH PAGE

Do not force every page into the same layout.

Each page should have a layout appropriate to its purpose.

For example:
- Landing pages should focus on clear information hierarchy and meaningful calls to action.
- Login pages should be simple and distraction-free.
- Dashboards should prioritize useful information and quick navigation.
- Data tables should prioritize readability and usability.
- Forms should be organized logically.
- Admin panels should prioritize productivity and information density.
- Profile pages should present information clearly.

Maintain the same design language throughout the website while allowing individual pages to have their own appropriate layouts.

## 5. FUNCTIONALITY MUST BE REAL

Never prioritize appearance over functionality.

- Every button must perform its intended action.
- Every form must have proper validation.
- Every navigation link must work.
- Every dropdown must behave correctly.
- Implement proper loading states.
- Implement success and error feedback.
- Implement empty states where appropriate.
- Handle API failures properly.
- Avoid fake data in production features.
- Do not create decorative controls that do nothing.
- Ensure frontend and backend functionality work together.

## 6. RESPONSIVE DESIGN

Develop a genuinely responsive website.

Test and optimize for:
- Desktop.
- Laptop.
- Tablet.
- Mobile phones.

Avoid simply shrinking the desktop layout to fit mobile screens.

Adjust navigation, spacing, typography, tables, forms, images and component layouts according to the available screen size.

Prevent horizontal scrolling unless it is intentional and necessary.

## 7. ANIMATIONS AND INTERACTIONS

- Use animations only when they improve usability.
- Prefer subtle and natural transitions.
- Avoid excessive entrance animations.
- Avoid unnecessary parallax effects.
- Avoid constantly moving backgrounds.
- Avoid excessive hover effects.
- Respect reduced-motion accessibility preferences.
- Ensure animations do not interfere with functionality.

The website should feel smooth and responsive, not like a flashy design demonstration.

## 8. CODE QUALITY AND ARCHITECTURE

Write code like a professional software engineer.

- Maintain a clean folder structure.
- Create reusable components when appropriate.
- Avoid unnecessarily large components.
- Avoid duplicate code.
- Follow consistent naming conventions.
- Keep frontend, backend, database and business logic properly separated.
- Avoid unnecessary dependencies and libraries.
- Remove unused imports, files and packages when safe.
- Avoid unnecessary abstractions and overengineering.
- Follow the existing project architecture.
- Do not rewrite working code without a valid reason.
- Keep code understandable and maintainable.

Do not introduce unnecessary complexity simply to make the project look sophisticated.

## 9. SECURITY AND PERFORMANCE

- Never expose API keys, secrets, database credentials or private configuration in frontend code.
- Validate input on both frontend and backend.
- Implement proper authentication and backend authorization.
- Protect sensitive API endpoints.
- Secure password storage.
- Prevent unauthorized access to restricted pages and data.
- Handle errors without exposing sensitive internal information.
- Optimize images and assets.
- Avoid unnecessary API calls.
- Avoid unnecessary component re-rendering.
- Follow appropriate web security practices.

## 10. ACCESSIBILITY

- Use semantic HTML.
- Provide proper labels for form fields.
- Ensure keyboard navigation works.
- Maintain sufficient color contrast.
- Provide meaningful alternative text for relevant images.
- Make interactive elements accessible.
- Do not communicate important information using color alone.

## 11. CONTENT AND VISUAL AUTHENTICITY

- Use meaningful content related to the actual project.
- Avoid generic AI-generated marketing language.
- Avoid fake testimonials, reviews and statistics.
- Avoid unnecessary placeholder text.
- Use realistic data structures.
- Use relevant illustrations and images only when needed.
- Do not add unnecessary sections to make the website appear larger.

## 12. DEVELOPMENT WORKFLOW

Before making changes:

1. Inspect the existing project structure.
2. Understand the existing code and functionality.
3. Identify the current design system.
4. Understand the purpose of each page.
5. Identify existing bugs and inconsistencies.
6. Plan the changes before implementing them.

During development:

1. Make changes systematically.
2. Preserve existing working functionality.
3. Avoid unnecessary modifications.
4. Maintain consistent design across pages.
5. Test components after implementation.
6. Check responsiveness.
7. Check browser console errors.
8. Verify frontend-backend integration.

After development:

1. Test all important user flows.
2. Test forms and validation.
3. Test navigation and interactive elements.
4. Test different screen sizes.
5. Review security-sensitive functionality.
6. Remove unused code and temporary content.
7. Fix visible design inconsistencies.
8. Confirm that implemented features actually work.

## 13. IMPORTANT RULES FOR AI-ASSISTED DEVELOPMENT

- Do not blindly generate code based on assumptions.
- Do not invent features I have not requested.
- Do not unnecessarily redesign existing pages.
- Do not change the technology stack without my permission.
- Do not replace working components just because you prefer another implementation.
- Ask for clarification when an important requirement is unclear.
- Explain important architectural changes before making them.
- Do not claim something is implemented or tested unless it actually is.
- Prioritize the project's actual requirements over generic AI design trends.

## FINAL OBJECTIVE

I want a website that:

- Looks professionally designed, not AI-generated.
- Has its own visual identity.
- Has consistent and intentional UI/UX.
- Feels natural and intuitive to use.
- Has real, working functionality.
- Has clean and maintainable code.
- Is responsive across devices.
- Follows proper security practices.
- Does not contain unnecessary design elements or features.

**Think like a professional product designer and senior software engineer. Make deliberate design and development decisions instead of relying on generic AI-generated patterns.**

The final result should be indistinguishable in design quality and engineering discipline from a carefully developed professional software product.
